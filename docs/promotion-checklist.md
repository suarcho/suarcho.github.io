# Promotion checklist

The site is live. The goal now is to make it easy for a recruiter to find it, open it and use it.

## Done in the repository

- [x] Portfolio live at `https://suarcho.github.io/` (English) and `https://suarcho.github.io/es/` (Spanish).
- [x] Both CV PDFs include the portfolio URL.
- [x] The web CV includes the portfolio URL.
- [x] GitHub profile README points to the portfolio.

## Your turn

### LinkedIn

1. Open **Contact info → Website** and add `https://suarcho.github.io/` with the label **Portfolio**.
2. In **Featured**, add the same link so it is visible near the top of your profile.
3. Keep the headline aligned with the site: IT support, VoIP, networking, NOC or junior systems, with Platform Engineering as the direction.
4. Add the portfolio link to your LinkedIn “About” section if there is room.

### Google Search Console

1. Open <https://search.google.com/search-console/> and add a **URL prefix** property: `https://suarcho.github.io/`.
2. Choose **HTML file** verification and download the file Google gives you.
3. Put that file in this project's `public/` folder, then commit and push. After the deploy succeeds, click **Verify**.
4. Open **Sitemaps** and submit `https://suarcho.github.io/sitemap.xml`.

This helps your name and the site appear in search results when a recruiter searches for you.

### Applications

- Target roles: IT support, helpdesk, VoIP/telephony support, NOC, junior systems administrator.
- Where: LinkedIn, InfoJobs and Tecnoempleo; also check Madrid MSPs and VoIP providers directly.
- Each application: attach the CV in the language of the posting and include the portfolio link.
- Track applications in a simple sheet: company, role, date, contact, status, next step.
- Aim for a steady pace (for example, five well-targeted applications per week) rather than many untailored ones.

### Later, optional

- Custom domain: `suarch.is-a.dev` (free, community-run, and **you** must author the request) or `suarch.dev` (paid, fully yours and more stable).
- Next technical milestone: IncidentOps in its own repository, or a smaller CI/CD case study that strengthens the platform narrative.

## What not to do

- Do not edit files in `dist/`; they are regenerated by `npm run build`.
- Do not add a custom domain only in GitHub settings without updating `astro.config.mjs`, `public/robots.txt` and `public/sitemap.xml`.
- Do not publish a `CNAME` file before the domain is approved.
